# v0.1.3 — Automatic learning persistence

This release fixes a behavioral gap discovered during a real Finviz task: the agent completed the browser task but did not perform the prose-only post-task instruction to create site-specific knowledge.

## New invariant

Reusable discovery is now represented in tool state, not merely in instructions.

- The first successful snapshot/click/fill/press/extract on an unknown site automatically creates `sites/<site>/SKILL.md`, `site.yaml`, and `actions.ts`.
- Successful `extract` calls automatically encode a reusable read action, verify the encoded representation through `webctl`, and promote it from Encoded to Candidate when verification passes.
- Unencoded click/fill/press discoveries cause `learning_pending: true` to be returned by discovery commands.
- `webctl learning status --session <id>` reports unresolved learning debt.
- The General `SKILL.md` forbids reporting task completion while reusable `learning_pending` work remains.
- Candidate becomes Verified only after successful execution in at least two distinct task sessions.

## Safety boundary

The runtime does not automatically synthesize arbitrary multi-step write workflows from raw clicks. Such flows remain pending until the agent encodes a verified declarative workflow or `actions.ts` implementation. Extracted values are never written into site knowledge or the learning journal.
